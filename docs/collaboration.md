# 多维护者协作与 macOS 启动

0.13 提供本地人员账号、管理员/维护者/观察者角色、Waker 范围授权、Skill 与基础配置协作、人员变更记录。运行架构是 Go 服务、SQLite 和 React 浏览器界面，不依赖 SSO。

## 新建协作实例

下载对应平台的发布包后，先在宿主机初始化管理员，密码由终端交互输入：

```bash
export QW_ROOT="$HOME/qoderwake-panel-data"
./panel init-admin --root "$QW_ROOT" --username owner --name 管理员
./panel serve --root "$QW_ROOT"
```

浏览器访问 `http://127.0.0.1:19831/`。在“维护者”页面创建人员账号、选择角色和管理范围。多人使用同一服务地址及各自账号；其他机器通过已有网络入口或 SSH 隧道连接。

macOS 默认从当前用户的 `.qoderwake` 目录读取 daemon 信息，优先采用 `run/daemon.port` 中的端口。可以用 `--home`、`--daemon-url`、`--daemon-bin` 指定其他实例；这些选项只改变 Panel 的连接目标。

1.1.13 的 macOS 安装可能将本地认证 token 保存为 `os-credential-v1`。Panel 使用现有官方 `qoderwake` 的 Bun 运行模式和系统凭据读取能力，在内存中解开该版本格式，然后建立 `client=cli` 的 HTTP 会话。辅助程序只读取已有钥匙串项，不创建、改写或导出凭据文件；业务操作仍走 HTTP。此适配已按国际版 `qoderwake.auth.v1` 验证，其他服务名可显式设置 `QW_DAEMON_CREDENTIAL_SERVICE`。

系统钥匙串不可用时，需要在宿主机恢复该用户的凭据库访问，再重试连接。Panel 不自动解锁钥匙串、注销官方账号或重建认证。未知加密版本和不支持的运行时会返回具体错误；不会将密文作为 Bearer 发送。

二进制内已包含前端和数据库驱动。Python 启动脚本保留为旧实现的回归对照，新实例使用 `panel serve`。

一个数据目录只允许一个新启动入口实例。再次启动会提示已有实例；退出前台进程后可以重新启动，用户、会话与审计保留在数据目录。

## 权限范围

| 角色 | 角色能力 |
|---|---|
| 管理员 | 人员账号、角色和范围管理；全部现有管理功能 |
| 维护者 | 分配 Waker 的基础配置和 Skill；对应正文、历史、差异与变更记录 |
| 观察者 | 分配 Waker 的配置、Skill 与变更记录，只读 |

维护者可修改 Waker 名称、描述与已有 Skill 启停。“官方操作”页还提供其 Waker 范围内的项目、MCP、技能、权限与记忆读取，以及部分配置、技能维护。共享 Provider、密钥、全局网络与进程控制、模型偏好、运行消费继续仅管理员可用。完整操作与参数见 [官方操作说明](cli-operations.md)及[逐项权限清单](cli-coverage.md)。

授权在后端执行。列表和缓存返回值按人员范围筛选；直接传入其他 Waker ID 也会被拒绝。受限角色可在官方操作页读取其 Waker 的 agent 记忆；项目记忆、聊天正文、全局用量、原始日志与文件下载仍由管理员访问。变更记录只返回当前范围内的维护操作，不包含其他人员 IP。

程序 caller key 继续使用既有调用范围、有效期和请求额度，不参与人员登录。Panel 权限仅约束经 Panel 的操作；宿主机文件权限和官方 Console 的权限仍由各自系统管理。

## 协作修改

从“维护资源 → 技能编辑”进入工作区，左侧选择 Waker 与技能，右侧编辑正文。“保存修改”位于对象标题旁，显示当前版本与未保存状态；macOS 使用 `⌘ S`，Linux 使用 `Ctrl S`。正文与“版本与差异”视图共享当前对象，选择“恢复此版本”后再填写恢复原因。

切换技能、Waker、页面或退出登录时，未保存草稿会先提示确认。`⌘ K` / `Ctrl K` 可定位导航的页面查找。实例连接与当前账号集中在顶栏；外观可跟随系统，也可选择浅色、深色、暖白或暖黑。

Skill 保存和回滚携带读取时的 `baseVersionId`；Waker 更新携带 `baseRevision`。当前版本发生变化时返回 HTTP 409，编辑框保留草稿并展示读取内容、当前内容和待提交修改。用户重新读取后合并，Panel 不自动覆盖冲突。

Waker 版本由可编辑字段计算。Panel 对自身的写入进行锁定和版本校验；Waker 更新及回滚与官方 Console/外部编辑器之间的竞争，仍受上游是否支持原子条件写入影响。不能将 Panel 内的并发验证外推到所有外部写入方。

审计记录稳定 user_id、操作、资源、结果及可观察的前后版本。消息、密码、Provider 密钥和 Skill 正文不写入审计。写入成功后，即使版本回读失败，也不会误报为写入失败；该次记录的后版本留空。

账号被禁用、权限变更或密码重置后，原会话失效。尚未执行的人员请求在进入业务处理前再次检查权限；已提交给 daemon 的任务不会因账号变更自动取消。

## 现有共享令牌实例的迁移

1. 停止待升级的 Panel，保留旧代码、启动配置和一致的 `access.db`/`usage.db` 备份。
2. 使用新代码读取数据。新增表和列保留原有审计、caller 配额及 pending/unknown 删除事务；历史 token/session 记录保持原主体。
3. 在同一数据目录执行 `init-admin`。这一步明确切换为人员账号模式，停用共享 admin/viewer Bearer、令牌登录及旧 Cookie 迁移入口，并撤销旧共享会话。旧令牌文件保留在原位置，程序 caller key 保留。
4. 用管理员账号验证登录、资源范围、协作保存和审计，再建立维护者账号。

还没有初始化人员账号的旧实例继续使用原来的共享令牌模式。新启动入口默认要求初始化人员账号；确需保持旧模式时显式传入 `--legacy`。

回退旧代码前需要停止服务，并按迁移前备份恢复匹配的数据库。恢复旧库会舍弃备份之后的新账号、会话和审计变化，不能将它当作保留新记录的原地降级。

至少保留一位启用的管理员。忘记密码时，可由有宿主机访问权限的维护者使用本地恢复入口：

```bash
./panel reset-password --root "$QW_ROOT" --username owner
```

恢复只重置指定人员密码并撤销其会话，不修改 daemon 认证、Provider 密钥或程序 caller key。

## 用户登录后自启

`panel service-config` 可生成 macOS LaunchAgent 或 Linux systemd 用户服务文件，检查后由维护者加载。完整命令见 [部署说明](deployment.md)。Panel 与官方 QoderWake App 分别管理，生成服务文件本身不启动或停止官方 daemon。

## 验证方式

Go 的 `internal/auth` 和 `internal/server` 测试覆盖人员身份、旧入口切换、资源范围、撤权、并发修改和审计，并保留与 Python 数据格式的对照。平台隔离验证和真实实例切换分别执行；当前版本的结果见 [发布说明](releases/0.13.0-rc.1.md)。
