# 记忆页

Panel 0.12.5 的记忆页仅向管理员开放。选择机器人后，面板根据官方 `employeeType` 读取相应记忆。

| 机器人类型 | 显示内容 |
|---|---|
| `personal_avatar`（我的分身） | 正式分身记忆，以及单独折叠的工作区记忆文件 |
| 其他 Waker | 工作区索引、主题和会话记忆文件 |

分身记忆来自官方 `/personal-avatar/learning/graph`，工作区文件来自 `/memory?view=all`。两个来源分别报告读取结果：正式记忆未初始化时，页面显示设置提示，已有文件仍可查看。记忆正文只读；写入继续通过分身对话中的记忆工具完成。

## 首次设置与故障处理

QoderWake 1.1.12 的个人分身支持文件模式和接入钉钉的模式。在官方控制台完成对应设置后，再使用记忆工具。

- `PERSONAL_AVATAR_DWS_LOGIN_REQUIRED`：分身身份解析需要钉钉登录。只使用本地文件时，完成官方文件模式设置；需要钉钉数据时，完成 DWS 登录。
- `PERSONAL_AVATAR_OWNER_REQUIRED`：在官方控制台重新登录当前所有者账号。
- `PERSONAL_AVATAR_ACCOUNT_CHANGED`：重新确认当前身份及分身记忆设置。
- 单次上游响应超过 1 MiB：到官方控制台查看。0.12.6 起，单条文件正文超过 200 KiB 时显示前部内容并提示截断，其他文档继续显示；条目数量截断也会提示。

当前源码的未发布修复也对正式分身记忆提供 200 KiB 正文预览，保留其他记忆并标记截断；版本记录见 [Changelog](../CHANGELOG.md)。

纯文件模式的官方初始化接口为 `POST /api/agents/:agentId/personal-avatar/input/files/prepare`，请求体为 `{"imEnabled":false}`，需使用该实例已授权的官方身份。该操作会创建持久绑定，运维执行前应保留数据库一致备份，并先确定使用文件模式。Panel 的记忆读取请求不自动初始化或切换模式。

## MCP 与重启验收

内置记忆 MCP token 由 daemon 实例生成。官方会在启动准备和会话运行时刷新所需配置；运维脚本不应把一次取得的 token 当作长期凭据复制给所有 Waker。

验收应包含以下证据：

1. 实际会话中的 MCP 握手和工具目录可用。
2. `memory_create` 返回成功，并能在正式记忆接口读到对应记录。
3. 新会话通过 `memory_recall` 找到同一记录。
4. 受管重启后重复握手和召回，确认配置刷新与数据持久化。

验收内容使用可识别的合成数据，完成后通过官方接口删除。普通 `Write` / `Read` 工具可以保存和读取文件，但不能作为记忆 MCP 验收证据。
